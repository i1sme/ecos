# Дизайн: Кризис → разорение (реализация стоимости)

**Дата:** 2026-06-01
**Условная нумерация:** Phase 25 (экономическое углубление; независима от ветки слотов 2C/2D)
**Направление:** глубина симуляции → марксистская верность
**Объём:** одна фаза. TRPF, цикл бум-крах, империализм — отдельные последующие фазы.

---

## 1. Постановка проблемы

Сейчас контур «кризис → разорение» физически разорван. В `PRODUCE-ALL`
([simulate.cob:893](../../../cobol/simulate.cob)) стоимость считается как
`OUTPUT = LABOUR × EFFICIENCY/1000`, прибавочная стоимость, накопление капитала и
зарплатный фонд выводятся **прямо из произведённой стоимости**. Рыночная цена
`WS-MKT-PRICE`, которую `CHECK-CRISIS` ([simulate.cob:1021](../../../cobol/simulate.cob))
роняет при перепроизводстве, **нигде не возвращается** в экономику политии.

Следствия:
- Реализованная стоимость **всегда равна** произведённой → рынок декоративен.
- Кризис перепроизводства роняет цену и иногда триггерит `CRISIS-WAR`, но не
  вызывает ни банкротств, ни безработицы, ни обнищания.
- `LABOUR-HOURS = POPULATION × 5` жёстко (`DEMOGRAPHY-ALL:2073`) — нет понятия
  занятости / резервной армии труда.
- Капитал только растёт (исключения: военный захват, обвал шахты).

Это противоречит центральному тезису проекта: COBOL должен считать
**противоречия** капитализма, а главное из них — кризис перепроизводства — сейчас
наполовину бутафорское.

## 2. Марксистская идея

Товар должен совершить «salto mortale» — продажу. Произведённая стоимость
становится действительной только через реализацию на рынке. Если рынок
перенасыщен, цена падает ниже стоимости, прибавочная стоимость не возвращается
капиталисту, капитал **обесценивается**, рабочих **увольняют** (промышленная
резервная армия), потребление падает, растёт **обнищание** — а с ним напряжение
и классовое сознание. Кризис перестаёт быть внешним триггером и становится
эндогенным **двигателем обнищания**.

## 3. Ядро механики

### 3.1. Реализация стоимости

Вводится новый параграф **`REALIZE-ALL`**, выполняемый **после** `CHECK-CRISIS` и
`PROPAGATE-CRISIS` (когда цены текущего хода уже скорректированы перепроизводством).
Накопление капитала и расчёт зарплатного фонда **переносятся** из `PRODUCE-ALL` в
`REALIZE-ALL`. Это архитектурно соответствует теории: производство и реализация —
разные моменты.

- `PRODUCE-ALL` остаётся ответственным за `OUTPUT-VALUE` и `SURPLUS-VAL`
  (произведённая стоимость и tech-модификаторы output). Накопление и wage из него
  убираются.
- Tech-бонусы накопления (Banking, Joint-Stock, Cartels, ORG L4 — строки 964–998)
  переезжают в `REALIZE-ALL`.

Формулы (целочисленная арифметика через ‰, как везде в проекте):

```
good   = PRIMARY-GOOD(REGION-ID(idx))        *> товар политии
midx   = индекс good в WS-MKT (lookup как в MARKET-AGGREGATE)
REALIZE-PERMIL = MKT-PRICE(midx) × 1000 / MKT-DFLT(midx)   *> 1000 = базовая цена
                 (диапазон [500..3000] из-за клампа цены в 50%..300%)

REALIZED-OUTPUT  = OUTPUT-VALUE(idx) × REALIZE-PERMIL / 1000
SURPLUS-VAL      = OUTPUT-VALUE(idx) × SURPLUS-RATE(idx) / 100   *> произведённая m
WAGE-COST        = OUTPUT-VALUE(idx) − SURPLUS-VAL              *> стоимость раб. силы
REALIZED-PROFIT  = REALIZED-OUTPUT − WAGE-COST
```

Развязка по знаку прибыли:

```
ЕСЛИ REALIZED-PROFIT >= 0:
    *> нормальное накопление (как раньше) + tech-бонусы
    CAPITAL += REALIZED-PROFIT / CAPITAL-ACC-DIVISOR  (+ Banking/JointStk/...)
    WAGE-FUND = WAGE-COST                              *> рабочие получают полную стоимость
ИНАЧЕ (выручка не покрывает издержки рабочей силы — обвал цены):
    LOSS = WAGE-COST − REALIZED-OUTPUT
    CAPITAL -= LOSS / CRISIS-WRITEDOWN-DIVISOR          *> ОБЕСЦЕНИВАНИЕ КАПИТАЛА
    ЕСЛИ CAPITAL < 0: CAPITAL = 0
    WAGE-FUND = REALIZED-OUTPUT                         *> зарплаты урезаны до выручки → голод
    → событие BANKRUPTCY (при LOSS выше порога BANKRUPTCY-CHRON-MIN)
```

Поведение: при цене ниже ~70% базовой (`REALIZE-PERMIL < ~700`) выручка не
покрывает зарплатный фонд → капитал списывается, wage-fund рушится. В бум (дефицит,
цена ×3) сверхприбыль ускоряет накопление. Существующий клампинг цены
(`CLAMP-PRICE`, 50%–300%) уже ограничивает крайности.

### 3.2. Безработица — резервная армия труда (персистентное поле)

Новое поле политии `WS-UNEMPLOYMENT-PCT` (0..100), сохраняется между ходами.
Обновляется в конце `REALIZE-ALL`:

```
ЕСЛИ REALIZE-PERMIL < 1000:                            *> перепроизводство → сокращение
    TARGET = (1000 − REALIZE-PERMIL) / UNEMPLOYMENT-SCALE   *> realize=500 → ~25%
ИНАЧЕ:
    TARGET = 0                                          *> найм при подъёме
*> Резервная армия меняется с инерцией, не мгновенно:
UNEMPLOYMENT += (TARGET − UNEMPLOYMENT) / UNEMPLOYMENT-SMOOTHING
зажать в [0, 100]
```

Обратная связь на производство (в `PRODUCE-ALL`): эффективный труд снижается на долю
безработных —

```
EFFECTIVE-LABOUR = LABOUR-HOURS(idx) × (100 − UNEMPLOYMENT(idx)) / 100
OUTPUT = EFFECTIVE-LABOUR × EFFICIENCY/1000
```

Это замыкает саморегулирующийся микро-цикл: безработица ↓ output → ↓ supply →
↑ цена → ↑ realize → ↓ target → найм. Лаг в один ход (безработица хода N влияет на
output хода N+1) естественен.

### 3.3. Обнищание → напряжение и сознание

- **Голод** подключается автоматически: упавший `WAGE-FUND` < потребности →
  `DISTRIBUTE-ALL` (уже есть) → `SOCIAL-ALL` поднимает напряжение. Бесплатно.
- **Безработица напрямую** в `SOCIAL-ALL`: новый член
  `+ UNEMPLOYMENT(idx) / UNEMPLOYMENT-TENSION-WT` к `WS-TENSION-DELTA`.
- **Кризис учит** в `CONSCIOUSNESS-ALL`: при `UNEMPLOYMENT > UNEMPLOYMENT-CONSC-MIN`
  и наличии рабочего класса (artisans+merchants ≥ `CONSCIOUSNESS-URBAN-MIN`) — `+1`
  сознание. Это **заодно лечит** известную проблему «сознание растёт слишком
  медленно» — кризис обнажает противоречия, что марксистски точно.

## 4. Причинная цепь (новая)

```
перепроизводство (CHECK-CRISIS, есть) → цена ↓
  → реализация < производства (REALIZE-ALL, НОВОЕ)
     → капитал списывается + wage-fund ↓ (НОВОЕ)
        → голод (DISTRIBUTE-ALL, есть) ──┐
        → безработица ↑ (НОВОЕ) ─────────┤
                                          ├→ напряжение ↑ (SOCIAL-ALL)
                                          └→ сознание ↑ (CONSCIOUSNESS-ALL)
                                             → революция / CRISIS-WAR (есть)
  → безработица ↓ output(N+1) → ↓ supply → ↑ цена → восстановление (саморегуляция)
```

### Защита формата (решение «да, заодно»)

Раз формат меняется — добавляем дешёвую страховку именно там, где риск:
- **COBOL** (`WRITE-WORLD`): guard на длину записи — `IF FUNCTION LENGTH(TRIM) >`
  ожидаемой → `DISPLAY "WARN: polities.dat record drift" UPON SYSERR` (паттерн уже
  применялся в Phase 7 для world.dat).
- **Rust** (`parse_polities`): если длина строки < ожидаемой (167) — логировать
  предупреждение (через `eprintln!`/лог-файл), а не молча отдавать `unwrap_or(0)`.
  Минимальная замена «молчаливого мусора» на видимый сигнал рассинхрона.

Полноценное версионирование/контрольная сумма — отдельная задача направления
«фундамент», здесь только точечный guard.

## 6. Новые константы (78-level, блок балансировки)

Стартовые значения — гипотезы, подлежат тюнингу стресс-тестом:

```cobol
78 CRISIS-WRITEDOWN-DIVISOR  VALUE 5.    *> делитель списания капитала при убытке
78 UNEMPLOYMENT-SCALE        VALUE 20.   *> (1000−realize)/20 = target % безработицы
78 UNEMPLOYMENT-SMOOTHING    VALUE 3.    *> инерция резервной армии (движение к target)
78 UNEMPLOYMENT-TENSION-WT   VALUE 5.    *> делитель вклада безработицы в tension
78 UNEMPLOYMENT-CONSC-MIN    VALUE 15.   *> порог безработицы для +сознание
78 BANKRUPTCY-CHRON-MIN      VALUE 1000. *> минимальный LOSS для записи в хронику
78 REALIZE-MAX-PERMIL        VALUE 3000. *> кэп реализации (страховка от сверхприбыли)
```

## 7. Chronicle + UI

- **Chronicle:** новое событие `BANKRUPTCY` (капитал обесценен в кризис); цвет
  красный, входит в фильтры Politics/Climate. Текст вида
  `«Capital destroyed. Firms fail as prices collapse.»`
- **UI detail-панель** ([ui.rs](../../../src/ui.rs)): две новые строки —
  - **`Profit rate: N%`** — производная, считается в Rust на лету:
    `(output × realize − wage_cost) / capital`. Закрывает UX-разрыв «норма прибыли
    невидима».
  - **`Unemployment: N%`** — прямо из нового поля; цвет по порогам.

## 8. Тестирование, регрессия, баланс

- **Регрессия сдвинется намеренно** — экономика меняется по построению. После фазы
  зафиксировать новый baseline: `scripts/baseline.sh capture`. Старый baseline
  устаревает (как было при Phase 2A).
- **Главный риск — баланс.** Реализация может либо обанкротить всех (death spiral),
  либо сверхприбыль раздует накопление. Обязателен стресс-тест **500–1500 ходов** с
  проверкой инвариантов: мир не вымирает поголовно, капитал не уходит в 0 у всех,
  эпохи по-прежнему достигаются, революции случаются. Тюнинг делается **только**
  редактированием блока 78-level констант.
- **Компиляция** после каждого под-шага: `cobc -x -free` + `cargo build` (по духу
  CLAUDE.md «компилируй и проверяй»).
- **Документирование:** обновить `DEVLOG.md` и memory `project_ecos.md` (байтовая
  карта: 164→167, новое поле; новый параграф REALIZE-ALL; новый baseline).

## 10. Что НЕ входит (явный YAGNI)

- Структурный c/v и тенденция нормы прибыли к понижению (TRPF) — следующая фаза.
- Полный цикл бум-крах с фазами депрессии/восстановления.
- Экспорт капитала, неравный обмен, откат mode соседа (империализм) — отдельное
  направление.
- Полноценное версионирование формата данных — направление «фундамент».
